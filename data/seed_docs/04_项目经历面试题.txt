# 项目经历面试题库（含可直接使用的 STAR 素材）

## 1. 请介绍一个你做过的 RAG 项目

我做了一个面向个人面试备考的私有知识库问答系统。技术栈是 Python + Streamlit + FastAPI 风格的分层设计，
向量库用 Chroma，检索采用 BM25 加向量的混合架构并叠加轻量知识图谱，模型全部本地 Ollama 部署。
文档支持 PDF、Word、TXT、图片 OCR 和网页导入，能分块、打标签、增量更新。
系统还提供模拟面试、答案评分、学习统计和本地备份，所有数据保存在本机。

## 2. 这个项目的技术选型为什么这样定？

选择 Streamlit 是因为它低代码、上手快，适合单设备快速交付；
Chroma 是嵌入式向量库，无需独立服务，和 SQLite 一起让整个系统零外部依赖；
本地 Ollama 保证隐私和零调用成本；BM25 加向量混合检索是为了兼顾精确匹配与语义理解。

## 3. 项目中遇到的最大挑战是什么？怎么解决的？

挑战是初期检索不准：专业术语和数字经常漏召回，导致答案不完整甚至误答。
我做了三件事：一是引入 BM25 与向量混合并按权重融合，补上精确关键词通道；
二是优化分块，保护代码块和表格、保留标题上下文；
三是加答案三重校验和用户反馈，把错误案例回流。最终首条准确率和答案稳定性明显提升。

## 4. 你是怎么做性能优化的？

我用 L1 内存缓存加 L2 磁盘缓存，热点问题命中缓存直接返回，避免重复嵌入和生成；
检索阶段控制候选条数并做双阈值过滤，防止无关内容拖慢生成；
对文档入库做块级去重和增量更新，改一份资料只更新变化的块，不用全量重建。

## 5. 如果让你继续改进这个项目，你会做什么？

我会引入更强的重排序模型提升首条准确率；增加多用户与权限隔离；
把语音转写做成完整闭环；并补充系统化的离线评测流水线，用 Recall、MRR、忠实度指标量化每次迭代收益。
