# LLM 应用开发面试题库

## 1. LangChain 和 LangGraph 分别解决什么问题？

LangChain 提供模型、提示词、检索、工具等可组合组件，适合快速搭建链式调用；
LangGraph 面向有状态、多步骤、需要循环的复杂 Agent，用图来编排节点与边，
支持条件分支、循环、持久化和人工介入，适合需要多轮工具调用和状态管理的智能体。

## 2. 大模型幻觉是什么？工程上如何缓解？

幻觉是模型生成看似合理但与事实不符或无依据的内容。缓解手段：
用 RAG 把答案约束在检索资料内；在提示词中要求“无依据就说不知道”；
做答案与资料的交叉校验；降低温度 temperature；引入用户反馈闭环持续修正。

## 3. 为什么选择本地 Ollama 部署？

Ollama 能在本机一键运行开源大模型，数据和提示词不出本机，隐私安全、无 API 费用、可离线使用。
本系统默认用 qwen3.5:9b 做对话与视觉 OCR、qwen3-embedding:4b 做嵌入，
同时保留 DeepSeek 云端作为可切换备选，通过 .env 即可切换。

## 4. Agent 和 RAG 有什么区别和联系？

RAG 是“检索资料再生成”，核心是知识获取，流程相对固定；
Agent 以大模型为大脑，能自主规划、调用工具、根据观察决定下一步，强调决策与执行。
二者常结合：Agent 把 RAG 检索当作一个工具，在需要查资料时调用知识库。

## 5. 如何降低 RAG 问答的响应延迟？

一是加多级缓存，热点问题命中内存缓存可毫秒级返回；二是检索并行化、控制候选数量；
三是用流式输出让用户先看到部分内容；四是给嵌入和生成设置合理超时与较小模型。
本系统采用 L1 内存 + L2 磁盘两级缓存，常见问题无需重复检索和生成。

## 6. 提示词 Prompt 工程有哪些实用技巧？

明确角色与任务；给出清晰规则和约束；提供示例 few-shot；要求结构化输出（如 JSON）；
把参考资料与问题分开；对关键约束重复强调。好的提示词要可测试、可迭代。
